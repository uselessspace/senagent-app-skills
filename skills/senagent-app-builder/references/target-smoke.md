# 注册后最小验收

## 完成条件和授权

默认构建交付必须达到：本地工程与业务验证通过 → 目标注册启用 → 注册后最小真实验证通过。至少跑通一条代表性的完整业务链，有前端时验证真实页面和关键操作；这是一道最低门槛，不能替代需求中其他必要测试。

在规划阶段询问或复用已明确的目标 SenAgent、应用 ID、首次注册／更新、发布身份、测试用户、可创建实例与写入的数据范围、测试后保留／清理方式。涉及模型时确认小样本调用预算。不要临近交付才发现没有目标或权限；未知项可以边开发边澄清，但无回复不授权部署，不默认选生产目标。

用户明确只要本地工程或禁止部署时遵从，只能报告“本地阶段完成，目标验收未运行”。缺目标、凭据、平台审批、模型绑定或浏览器工具时，报告具体阻塞和已有证据，不写“整体通过”。已明确授权且目标／范围未变时继续推进，不重复询问。构建这个 Skill 本身不要求发布任意应用。

## 注册与身份

读取可用的 senagent-app-release Skill 执行打包、上传候选、首次审批／更新和安装核验。未安装时仍可依据当前 CLI help 与目标公开文档执行相同阶段；缺必需协议／权限才阻塞，不猜命令。先确认以下命令实际存在：

```bash
senagent app package --help
senagent app publish --help
senagent app approve --help
senagent client --help
```

本地 full 和 app test 通过后固定应用内容，制品写在应用树外。上传使用发布用用户凭据；个人凭据客户端不具备发布或平台审批权限。首次上传只是待审核候选，需平台管理员审阅同一摘要后批准；已有应用由归属人／应用管理员使用 publish --update。Skill 不代替平台审批，普通开发者不能自行提权通过门槛。只在服务实际确认当前版本／摘要已注册启用后，开始验收。

需要 OCI 时仍须明确镜像目标、架构和推送影响。不用 app dev 的源码链接或候选上传结果冒充制品注册。源树变化后重做受影响的验证、打包及安装，不能把旧目标结果关联到新源码。

## 注册后必须运行的一轮

1. **目标与实例**：确认安装版本／摘要、当前使用资格和后端就绪。用已授权测试身份创建独立测试实例，记录实例 ID；不能把打开平台首页当应用验证。
2. **后端**：通过 Runtime 公开入口调用一项代表性业务能力，检查结构化结果。写入型应用至少完成“创建最小测试对象 → 重新查询读回”，检查真实持久化；只读应用验证已知测试数据的结果。再执行一条适用的非法参数／不存在对象／越权反例，确认明确失败且没有意外副作用。health 成功不足以证明业务通过。
3. **Agent／模型**：应用依赖 Agent 或模型时，用一条最小真实请求验证关键链。等待最终完成或明确失败，检查最终 message.completed／公开结果与业务对象；action 返回受理或 Turn ID 不算通过。等待用户选择时按测试计划响应；模型未绑定、失败、超时或缺预算属于未通过，不用固定模型替代真实链。
4. **前端**：有 Surface 时，在真实目标宿主中打开安装制品的页面，检查生产资源、握手和身份；执行一次关键操作，确认页面显示后端真实结果，刷新后仍正确。验证一条适用的空／错误状态；要求 ACK 的命令需 completed ACK。HTTP 200、静态 HTML 存在或 CLI 操作成功都不能替代浏览器验证。无 Surface 标记不适用；有 Surface 而无浏览器能力则标记阻塞。
5. **应用 CLI**：用户确认需要配套 CLI 时，从其安装入口运行本轮代表性命令并核对结果，按 [CLI 验收](external-cli.md) 记录。平台客户端仅作为验证驱动，不代替约定的应用 CLI。
6. **收尾**：按已确认范围清理或保留本次实例／对象，记录最终状态与失败资源；清理不得扩大到其他实例或组织数据。验证失败时修复、重发并重验，不仅改报告。

## 优先使用现有 CLI，缺项使用公开 API／浏览器

目标已开放个人凭据且用户已提供测试凭据时，先读取 contract 与 instances，再执行 create-instance、operation 或 action。命令示例中的路径和 ID 必须替换为真实目标，副作用与模型预算先获得授权：

```bash
senagent client --credential-file /private/test-credential.json contract
senagent client --credential-file /private/test-credential.json create-instance --name "应用最小验收" --confirm
senagent client --credential-file /private/test-credential.json operation \
  --instance INSTANCE_ID --surface SURFACE_ID --operation OPERATION_ID \
  --payload-file /private/test-request.json --confirm
```

只使用 contract 中的真实 ID 和输入 Schema；只读操作不强加确认。凭据文件在应用工程外，不能打印其内容。`--confirm` 不是强审批凭证。

当前客户端没有通用的轮次等待／最终消息读取、实例删除或浏览器验收子命令，不能发明 `app e2e`、`client wait` 等命令。这些步骤根据目标 OpenAPI 使用授权公开 API 或 Studio／浏览器；action 的 JSON 和退出码只证明受理。纯 Chat 应用也可用公开 Turn API 或 Studio 验证，不为了测试添加虚假 Surface。

使用 CLI 做验收不意味着用户同意产品开放新的外部业务能力。目标未开放个人凭据时可用已授权登录身份的公开 API／Studio；不要为了完成测试自动开启个人凭据策略或新增外部入口。如果现有公开能力无法完成必要步骤，明确报告缺口与阻塞。

## 验收证据

记录目标 URL、应用 ID／版本／摘要、时间、测试身份标识（无密钥）、实例／对象／Turn ID、命令与退出码、预期与实际结果、前端截图或操作记录、清理状态。证据放应用树外；本地、目标与 CLI 均指向同一安装版本。

逐项使用通过／失败／未运行／阻塞／不适用（理由），所有适用的最低门槛通过后才可称“整体通过”。最小验收不代表全功能、所有浏览器、性能或全部权限矩阵都已验证；其余必要测试仍按需求执行。
