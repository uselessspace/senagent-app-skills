# 从需求到可运行应用

默认完成条件是本地工程与业务验证通过、目标已注册启用、注册后一轮最小真实验证通过，见 [注册后最小验收](../../senagent-app-verify/references/target-smoke.md)。本地验证命令自身不会注册应用，Coding Agent 必须继续完成已授权的后续阶段。用户明确限制为本地时仅交付该阶段，不称整体通过。

用户可以只说：“使用 $senagent-app-builder，帮我开发一个资料归档应用。”
语言选型、敏感操作默认确认、测试和阶段说明由 Skill 主动承担，不要求用户重复这些规则。

## 开始前的可用性

Skill 提供开发指导、公开 Schema、测试资产和辅助脚本；CLI 提供 scaffold／verify／test／package／publish 等实际命令。两者独立分发，Python／Go 工具链按选型准备。检查 PATH 或用户明确提供的独立 CLI；缺少时说明阻塞的生成／官方验证步骤，需求澄清与设计仍可继续。不要要求用户下载 Runtime 源码，不自动安装全局软件，缺工具不能记为验证通过。

## 每一步做什么

| 阶段 | 位置与内容 | 能证明什么／不能证明什么 |
| --- | --- | --- |
| 工程校验 | 开发者电脑；检查 application.yaml、引用、Schema、Agent 工具／能力声明、依赖和构建 | 工程满足已检查的结构与构建条件；不证明授权策略实现正确 |
| 应用启动检查 | 开发者电脑；临时启动应用自己的后端，使用自建数据测 health、实例初始化／幂等／删除及清理 | 后端基础协议可用；不会在 SenAgent 服务里注册应用，也不是部署另一套 Runtime |
| 业务测试 | 开发者电脑；运行应用声明的测试，读取真实 fixture 状态、检查权限和副作用 | 仅证明已执行断言；未连接真实入口的框架自测不能冒充应用验收 |
| 打包 | 开发者电脑；生成用户应用制品 | 已生成包；没有上传或注册。选择 OCI 参数时另有构建／推镜像影响，须明确授权 |
| 上传候选 | CLI 将应用制品通过 API 提交到指定 SenAgent 服务 | 候选存在；还没注册启用，不自动执行应用代码 |
| 注册启用 | 指定 SenAgent 服务；审阅权限、内容摘要及替换影响后确认，由服务验证安装 | 以服务返回的注册／启用状态为准，失败不能宣告完成 |
| 服务内联调 | 已注册启用的指定 SenAgent 服务；创建获授权测试实例，验证 Chat／模型／权限／Surface | 才能提供真实运行证据；涉及模型预算和测试数据的操作另需明确范围 |

“本地”始终指开发者电脑上的工程和应用进程检查，不表示 SenAgent 必须部署在同一台电脑。
SenAgent 服务可在本机或内网服务器；服务器不需要、也不应读取开发者电脑目录。
`app verify --profile full` 组合构建与启动检查；`app test` 执行独立测试计划。二者都不自动上传、注册或调用模型。
依赖安装可能访问配置的包仓库，所以“本地验证”不等于“完全断网”。只运行可信应用代码，使用临时数据，不接真实业务库。

真实 Agent 执行、Chat 选项暂停／恢复、模型归因、宿主内 Surface 行为，不能仅靠这两条命令确认。登录、快照联调和候选确认只按 CLI help 与目标服务实际提供的能力执行，不虚构命令或用共享目录替代。

## 如何向用户报告

使用明确阶段，避免仅说“本地通过”“未发布”或“已发布”：

- 本地阶段完成时：“工程与启动检查通过，业务测试通过／失败／未运行；目标注册及最小真实验收待执行／阻塞，尚未整体通过。”
- 整体通过时：“目标确认注册启用，后端最小业务链、适用的 Agent／模型、前端基础操作和约定 CLI 已验证；证据如下。”
- 打包完成时：“已生成制品及摘要，尚未上传候选。”
- 上传完成时：“已上传到指定服务，候选等待审阅，尚未注册启用。”
- 启用后：“服务确认注册启用成功；以下真实运行检查已完成，其余未运行。”

用户要求“发布”但没有明确目标或做到哪一步时，问清打包、上传候选还是注册启用。
用户已明确授权且内容、目标、影响未变，不重复索取同一确认；变化后重新展示并确认。

已确认需要外部调用时，开发完成还必须包含范围内的应用 CLI、安装／使用说明和命令级测试；逐项报告外部能力与真实 Runtime 联调状态。范围未确认、CLI 未完成或相关测试未运行时，不得宣称该部分完成。

## 产品边界

开发者正常工作区只有其应用源码，集成依赖仅为独立 CLI、Skill 和公开协议。
Runtime 源码不属于开发者交付物，正常开发入口不提供修改 Runtime 程序文件的权限；保护由发行和部署落实。
这条产品要求不能靠“请勿修改 Runtime”的用户提示词实现，也不以维护者源码模式替代独立 CLI。
