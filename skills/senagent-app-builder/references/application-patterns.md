# 从两个实际应用提炼的模式

只摘可复用的设计模式，不复制两个应用的业务实现、依赖或参数。

## 个人知识空间（Python）

- manifest v4 + backend HTTP v2；FastAPI 路由只做 HTTP 转换，独立存储模块维护业务事实，React 工作台是应用内的独立前端。
- 协调 Agent 委派给原文导航、内容问答、知识库维护、文档整理、回答档案等专业角色。不同读／写／删除工具白名单是分工理由，不是按每个工具拆角色。
- 删除文档 Skill 先读取最新目录，冻结稳定 ID；一次 Chat 选择确认完整范围，一次批量删除；目标过期重读后重新确认。
- 回答清理与源文档删除分开，确认文案写清哪些对象不受影响。organization 业务库与实例回答／历史分开。
- 删除默认都需确认，不按对象是否为空建立绕过路径。
- 后端删除入口校验角色并调用事务性存储，并不能由此推断它验证了可信用户审批记录。不要把现有示例误认为高保证审批实现。
- 新应用显式声明真实测试命令；构建成功不代表业务测试通过。

## 今晚的故事（Go）

- cmd 入口、httpapi、story 模型、sqlitestore 及版本化 SQL 迁移；前端独立故事工作台。
- 一个 story-author Agent 串联偏好／创作／正文保存／插图／导航；正文先提交，后续媒体失败不撤销正文、不重复创作。
- 页级朗读通过 Surface capability operation 执行，不必新建 Agent Turn 或发送无意义 Chat 回执。
- 原稿属于实例，共享发布是带独立权限／生命周期的快照，不是放开原稿 URL。
- 删除通过 Surface DeleteDialog，随后调用 stories.delete；不能只检验存在弹窗就认定后端有不可绕过审批。
- 有 ASR 能力声明，但清单说明录音按钮尚未开放；能力声明不等于可用功能。

## 不直接继承的东西

供应商名称、默认虚拟模型 ID、具体页数／工具次数／前端样式、绝对路径和应用专属业务规则都不是平台开发规范。新应用必须完整声明锁定安装／测试／构建。

选择模式：职责与权限独立时参考知识空间分角色；单一目标与一致上下文时参考故事应用单角色。无论哪种语言，数据权限、敏感操作确认和 HTTP 边界要求一致。
