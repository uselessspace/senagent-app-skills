# 身份、数据与密钥边界

每个私有 Runtime 持有部署者配置的一个长期 SDK Key，安装包不固化 Key。Runtime 已验证的当前用户凭据（OIDC 登录 Token 或应用绑定的个人凭据）与 SDK Key 同时用于网关交互，不做新的凭据交换。

Runtime 验证身份及应用授权。网关按 Key 确定消费者、权威计费组织、模型授权和限流；当前用户凭据只随调用携带，网关不解析／持久化它。个人凭据必须由 Runtime 每次恢复真实 actor 并重新校验当前应用资格，不是 OIDC Token 或角色快照；外部客户端接入见 [外部调用与应用 CLI](external-cli.md)。用户／部门／应用／Agent 标签由 Runtime 提供，是 Key 组织下的归因，不能覆盖 Key 的账单组织。开发／生产使用同 Key 可汇总，不同 Key 可分算，环境由部署者自行隔离。

应用后端拿不到 SDK Key 和原始当前用户凭据；Surface 也拿不到后端 service token。先验证 Runtime service token／协议，再信任它传递的 actor、应用归属人和实例归属人上下文。不接受浏览器伪造 header、工具参数中的 subject／role／scope，也不把归属人 ID 当成业务授权结果。

## 身份与归属

- actor：本次实际操作用户，审计、Chat 署名和模型归因使用它。
- application owner：应用治理归属，用于应用发布和管理，不自动产生业务数据权限。
- instance owner：当前实例归属，用于实例成员和生命周期语义，不自动把 owner 的业务身份授予 actor。
- Agent `data_permissions` 是模型可调用能力白名单，不是人类用户的业务角色或行级权限。
- Runtime 控制应用／实例入口；应用后端以 actor 为实际操作者，在自有数据库中查询业务角色与对象 ACL。任何管理角色都不代替敏感操作确认。

测试 A 的实例邀请 B：请求中 actor=B、instance owner=A；后端仍以 B 审计和鉴权。若产品明确选择“实例成员共享当前工作区”，由应用自己实现该实例内规则；B 创建新实例不继承 A 的业务权限。同组织、应用 owner 或实例 owner 都不自动获得全库可见。

## 个人数据与轮次可见性

业务数据范围与轮次可见性分别决定。需要将用户私有内容交给 Agent 时，声明 `agent_turn_visibility: actor` 并要求可信后端请求的可见性保证，接法见 [HTTP 契约](backend-http.md)。默认 `instance` 不能用来承载只对 actor 开放的个人内容。用户级授权可以跨实例生效，实例授权仅限本实例；应用自己的回答、文档、资源和缓存仍执行业务 ACL，群聊仍是实例共享。

规划和验收覆盖同实例 A／B 的 Chat、工具结果、历史、工作区和生成物隔离；撤权后的读取拒绝；清单从 actor 改为 instance 后旧轮次仍私有；共享轮次不能读取自己的旧私有上下文；私有轮次不能写实例共享 Agent 状态。后端单测与真实 Runtime 的隔离测试分别报告。

## 数据与迁移

默认 data_scope=instance，新实例空。organization 必须显式声明且后端过滤数据；Chat、记忆、回答、私有生成物／界面状态仍按实例隔离。共享发布复制成独立资产，不直接放宽原稿访问。

后端是业务事实源，Chat／Agent state／前端状态不是第二套数据库。事务成功后才发同步命令，前端拉取真实结果。幂等重试、版本冲突、权限变化、缓存／索引失效要有测试。

实例删除物理清理其私有数据，不能清掉组织共享库；明确界定哪些副本仍保留。应用迁移用新文件，测试空库／旧库／重复启动／失败恢复。Runtime 不迁移业务库，同模板只运行当前发布版本，回退代码不能替代数据恢复。

不能通过读 Runtime 内部数据库验证业务或构造确认凭证。不能把宿主全部环境或真实凭据写进示例／测试快照／报告。

## IAM 归属与目录边界

平台管理员、应用开发者、应用 owner/administrator、实例成员和业务数据权限相互独立。应用归属与管理由 SenAgent 记录；第一次注册需要平台批准，提交者成为 owner；后续由 owner/administrator 更新并自动校验。成为应用归属人不自动获得全组织数据权限。

组织目录只提供已授权范围内的稳定标识与名称。应用保存自己的业务共享与管理规则，历史部门 ID 不因显示名称加载失败而改写或清空。不要使用 Runtime 管理接口替代应用目录能力。完整接法见 protocols.md。
