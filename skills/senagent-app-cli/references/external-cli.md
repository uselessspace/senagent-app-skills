# 外部调用与应用 CLI

## 先确认范围

新建应用必须询问是否需要外部系统、脚本或 Coding Agent 调用应用能力；已有明确答案直接沿用。需要时，先基于业务需求列出候选能力，向用户确认以下范围，之后才实现外部入口和配套 CLI：

- 谁调用、在哪运行：人工终端、Coding Agent、定时脚本或其他服务；目标系统、语言与安装方式。
- 哪些能力开放：逐项列出业务动作、对象范围、输入、结果、只读／写入／模型调用，以及明确不开放的能力。
- 身份和权限：以谁的身份调用、实例与组织范围、个人内容可见性、敏感操作的确认方式；无人值守是否需要及其授权边界。
- CLI 交付：命令名与参数、输出及退出码、文件输入输出、是否需要异步结果查询；确认复用平台 CLI 的应用命令封装，还是独立可安装 CLI。

将具体清单展示给用户确认并记录到 `APPLICATION_DESIGN.md`。例如用户只说“支持外部调用”，应追问“需要查询、上传、生成、删除中的哪些能力？由人操作还是脚本无人值守？”不能默认全开放。未回复不视为否定或同意，可继续不依赖答案的工作；迭代新增能力时复核范围，已确认且未变化的范围不重复问。

用户确认需要后，CLI 是应用交付的一部分，必须与对应后端能力同步构建、测试和提供使用说明；仅交付 HTTP 接口或几条通用 CLI 示例不能代替已确认的应用 CLI。用户明确不需要则记录不适用，不生成占位 CLI。

## 平台入口与客户端边界

先按 [CLI 选择与更新](../../senagent-app-builder/references/development-cli.md) 确认入口，再核对 `--version`、`--help`、`client --help` 和目标公开协议。以下裸 `senagent` 示例适用于独立安装环境；Studio 中必须替换为 Host 提供的 `"$SENAGENT_CLI"`。只使用当前个人凭据客户端和公开协议，不保留旧版调用路径。命令缺失时要求更新 CLI／目标并报告能力阻塞，可先完成应用内 CLI 参数、输出和本地测试，不猜私有 API。

现有客户端通过用户导出的应用绑定个人凭据访问 Runtime。只读发现示例（替换为用户明确提供的私有凭据文件路径）：

```bash
senagent client --credential-file /private/senagent-credential.json contract
senagent client --credential-file /private/senagent-credential.json instances
```

`contract` 用于核对当前应用声明的 operation／action；具体参数以 help 和目标契约为准。确定性业务优先调用 operation，需要 Agent 决策时调用 action。backend tool 白名单不等于外部 API：不能自动把全部 tools 导出，也不能把 service token 发给外部调用者。现有个人凭据入口与 Surface 声明关联；纯 Chat 应用、无 Surface 的操作或 capability operation 需要先核对公开入口是否支持，不为绕过限制伪造空界面或管理接口。

应用 CLI 源码、依赖、命令映射、构建产物和测试保留在应用工程中。复用平台 CLI 时采用参数数组调用并声明依赖版本；独立 CLI 只依赖公开 HTTP 契约。两者都不得导入 Runtime 内部包、直读数据库、直连模型网关或复制后端业务逻辑。CLI 未提供某个命令并不能阻止持凭据者手工请求接口，实际可访问范围必须由后端和公开授权机制执行。若用户要求的独立外部权限范围无法由现有协议保证，明确缺口，不能把客户端隐藏命令当授权。

## 凭据与确认

个人凭据绑定应用和真实用户；应用开放策略、撤销、过期、实例成员关系和业务 ACL 由服务端实时校验。应用治理身份不自动授予业务数据权限。用户凭据只提交 Runtime，应用后端仍使用 Runtime 验证的 actor 上下文。无人值守服务身份若目标协议不支持，不用平台管理员凭据或应用 service token 替代。

凭据使用用户提供的私有文件，POSIX 权限应为 0600，不放应用包、示例、参数值、日志或测试结果中。正常远程调用使用 HTTPS，不跟随携带凭据的重定向；开发 HTTP 仅在目标明确支持且用户选择时启用，不自动降级。不得自行创建、轮换凭据或开放平台个人凭据策略。

敏感命令先展示稳定对象、版本和影响范围，再按用户确认的交互／无人值守策略执行。非交互模式缺所需确认应失败，不能默认 yes。`--confirm` 或 `--yes` 只是客户端交互约定，不是后端可信人类审批证明；强审批按 [确认规则](../../senagent-app-builder/references/confirmation-and-chat.md) 实现，不能让 Coding Agent 自行设置参数冒充人类确认。构建 CLI 的授权不等于授权真实数据变更或付费模型调用。

## 命令与验收

只实现确认范围内的命令。提供 `--help`、机器可读 JSON、稳定非零失败退出码，stdout 放结果、stderr 放诊断；不把异常转换成空成功。写请求超时后查询真实结果，不盲目重试；后端持久化幂等与并发冲突规则。异步 action 返回受理／任务标识时，只能报告已受理；按公开能力查询完成状态，无法查询则明确未确认完成。

按实际命令在临时数据上测试并接入 `app test` 的 business／confirmation suite：

- 参数解析到公开请求、真实后端持久化及结果的完整链；每项确认能力至少一条成功和一条失败路径。
- 错误／过期／撤销凭据、跨应用／实例／对象、角色变化；用户要求的外部限制在服务端也不能被手工请求绕过。
- 取消与缺确认零写入、重复提交幂等、超时与异步结果不假成功；个人轮次结果不泄露给同实例其他成员。
- 从干净安装运行 CLI help 和代表性命令；不依赖开发者源码目录。范围排除项不在 CLI 命令清单中。

本地使用固定凭据与测试服务，真实 Runtime 联调需要已授权目标、测试身份和数据范围。分别报告已完成的 CLI 构建、命令测试、真实凭据／服务联调；不能用通用 CLI 可运行或后端 full 通过替代应用 CLI 验收。
